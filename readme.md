# Парсер отзывов — вариант 5

Итоговое задание по дисциплине «Теория и практика многопоточности».
Spring Boot MVC REST-приложение собирает текст, рейтинг (1–5), автора и дату отзыва
из HTML-страниц, сохраняет их в файловую H2 и возвращает JSON.

## 1. Запуск без настройки

1. Откройте `pom.xml` как Maven-проект в IntelliJ IDEA Community / Giga IDE.
2. Выберите JDK 17 или 21 и дождитесь загрузки зависимостей (при первом запуске нужен интернет).
3. Запустите `ru.study.reviews.ReviewParserApplication` кнопкой Run.
4. Откройте **http://localhost:8080/answer**. В течение нескольких секунд появятся **5 отзывов**.
   Если первый ответ пустой, обновите страницу: сбор асинхронный.

Никакие ключи, аккаунты, Docker, внешняя СУБД или переменные окружения не нужны.
Порт 8080 должен быть свободен. Данные автоматически создаются в `./data/` относительно
рабочей папки запуска и сохраняются между перезапусками.

Альтернативный запуск из терминала (JDK в `JAVA_HOME`):

```powershell
.\mvnw.cmd spring-boot:run
```

Linux/macOS:

```sh
sh mvnw spring-boot:run
```

## 2. Последовательность проверки API

### Запустить сбор двух страниц

**POST http://localhost:8080/parse**

Заголовок: `Content-Type: application/json`

```json
{
  "urls": [
    "http://localhost:8080/demo/product/1",
    "http://localhost:8080/demo/product/2"
  ]
}
```

PowerShell:

```powershell
$body = @{ urls = @('http://localhost:8080/demo/product/1', 'http://localhost:8080/demo/product/2') } | ConvertTo-Json
$job = Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/parse' -ContentType 'application/json' -Body $body
$job
Invoke-RestMethod "http://localhost:8080/jobs/$($job.id)"
```

Ответ — HTTP **202 Accepted**, `Location: /jobs/{id}` и объект задания:

```json
{
  "id": "UUID задания",
  "status": "RUNNING",
  "totalPages": 2,
  "completedPages": 0,
  "foundReviews": 0,
  "savedReviews": 0,
  "errors": {},
  "createdAt": "время создания ISO-8601"
}
```

Пример показывает структуру: счётчики и статус уже могут измениться к моменту ответа.
Выполняйте **GET http://localhost:8080/jobs/{id}**, подставив реальный `id`, до завершения.
Статусы: `RUNNING`, `COMPLETED`, `PARTIAL` (часть страниц с ошибкой), `FAILED` (все с ошибкой).
`foundReviews` — число распознанных отзывов; `savedReviews` — число новых записей.
При повторном сборе демонстрационных страниц `foundReviews = 5`, `savedReviews = 0`, поскольку
автосбор уже сохранил эти отзывы. Поле `errors` содержит ошибки по URL.
Состояние задания хранится в памяти; последние 200 заданий доступны до перезапуска,
при заполнении истории удаляется самое старое завершённое задание.

### Получить результаты

- Все отзывы: **GET http://localhost:8080/answer**
- Рейтинг по убыванию, только от 4: **GET http://localhost:8080/answer?sort=rating&direction=desc&minRating=4**
- Пагинация: **GET http://localhost:8080/answer?page=0&size=2**
- Дата по возрастанию: **GET http://localhost:8080/answer?sort=date&direction=asc**
- Автор (поиск подстроки без учёта регистра): **GET http://localhost:8080/answer?author=Анна**

Ответ содержит `content` (массив отзывов), `totalElements` (число после фильтрации до
пагинации), `page`, `size`. Отзыв содержит `id`, `sourceUrl`, `author`, `text`, `rating`,
`date`, `collectedAt`. Сортировка: `id`, `date`, `rating`, `author`; направление `asc`/`desc`.
По умолчанию — дата по убыванию, страница 0, размер 20. Размер страницы: 1–100.
Можно передать `sourceUrl` для точного совпадения (URL нужно кодировать как query-параметр).
При одинаковых значениях сортировки дополнительный ключ — `id` по возрастанию.

### Проверить ошибки

1. POST `/parse` с `{"urls":["http://localhost:8080/demo/product/99"]}`:
   запрос принят, задание перейдёт в `FAILED` с HTTP-ошибкой источника.
2. Передайте одновременно существующую и несуществующую демостраницу: получите `PARTIAL`.
3. POST `/parse` с `{"urls":[]}` или `{"urls":["file:///test"]}`: HTTP 400.
4. GET http://localhost:8080/answer?sort=unknown : HTTP 400.
5. GET `/jobs/{несуществующий-UUID}`: HTTP 404 (некорректный формат UUID — 400).

## 3. Какие источники поддерживаются

Две встроенные страницы — **учебные HTML-фикстуры**, а не данные реальных покупателей.
Они доступны по `/demo/product/1` и `/demo/product/2`, содержат JSON-LD и загружаются
парсером настоящим HTTP-запросом через `RestTemplate`, как внешние страницы.
Это обеспечивает воспроизводимую проверку без зависимости от CAPTCHA и сети.

Для внешнего источника передайте полный HTTP(S) URL страницы товара/обсуждения в `urls`.
Поддерживаются страницы со встроенными `<script type="application/ld+json">`, содержащими
Schema.org `Review` (включая вложенные `Product.review`, массивы и `@graph`). Нужны поля:

```json
{
  "@type": "Review",
  "author": { "name": "Автор" },
  "reviewBody": "Текст отзыва",
  "reviewRating": { "ratingValue": 5 },
  "datePublished": "2026-10-01"
}
```

Автор также может быть строкой, рейтинг — числом или строкой, дата — ISO-дата
или ISO timestamp с датой в первых 10 символах. Неполные/некорректные отзывы пропускаются.
Если пригодных отзывов нет, задание сообщает ошибку, не подставляя демонстрационные данные.

**Произвольные страницы Ozon, AliExpress и Отзовик не гарантируются:** если отзывы
загружаются JavaScript, требуют авторизации, CAPTCHA либо используют другую разметку,
нужен отдельный адаптер/официальный API. JavaScript здесь не исполняется, защиты не обходятся.
Обрабатывается только переданный HTML, без обхода ссылок и автоматической пагинации сайта.
Соблюдайте правила выбранного источника и ограничения на автоматический сбор.
Приложение предназначено для локальной учебной проверки: endpoint принимает также локальные
URL для демо, поэтому его нельзя публиковать в интернет без ограничения доступа и адресов источников.

## 4. Архитектура и многопоточность

Этапы реализации и соответствие требованиям:

| Требование | Реализация |
|---|---|
| MVC / Spring Boot | `ReviewController`, `DemoController` → сервисы → `ReviewRepository`; представление — JSON |
| Кастомный ExecutorService | `WorkerConfig`: `ThreadPoolExecutor`, 4 потока `review-worker-N`, очередь 32, `AbortPolicy` |
| Параллельный сбор | Каждая ссылка — независимая задача, до 20 ссылок в POST; очередь общая для всех заданий |
| Расписание | `DemoScheduler`: автосбор при старте и `@Scheduled` раз в 60 секунд; при активных заданиях очередной сбор пропускается |
| HTTP-взаимодействие | `RestTemplate`, connect timeout 5 секунд, read timeout 10 секунд |
| Хранилище | H2 file + Spring JDBC, схема создаётся автоматически |
| Извлечение и сортировка | `AnswerService`: чтение из H2 в immutable DTO, фильтрация и сортировка через `parallelStream()` |
| Потокобезопасность | `ConcurrentHashMap` заданий и ошибок, `AtomicInteger` счётчиков, immutable records |
| Защита от дублей | SHA-256 URL + автор + текст + рейтинг + дата; synchronized сохранение и UNIQUE в H2 |
| Выдача результата | `/answer`, фильтры, сортировка и пагинация; `/jobs/{id}` — прогресс |

Поток HTTP не ждёт завершения сбора. При переполнении очереди страница получает ошибку
в задании; если исчерпан лимит истории активными заданиями, POST возвращает 429.
Ошибка одной страницы не останавливает остальные. В логах видны URL и имена рабочих потоков.
Рабочий пул закрывается Spring при остановке приложения; завершение ограничено HTTP-таймаутами.
`parallelStream()` использует стандартный common ForkJoinPool отдельно от пула сбора.
Для учебного объёма все отзывы сначала загружаются в память; для больших объёмов нужны
SQL-фильтрация/пагинация и лимиты размера HTTP-ответа.

H2 Console: **http://localhost:8080/h2-console**

- JDBC URL: `jdbc:h2:file:./data/reviews`
- User: `sa`
- Password: пустой
- Пример SQL: `SELECT * FROM reviews ORDER BY rating DESC;`

Необязательные настройки находятся в `src/main/resources/application.properties`.
Отключить автосбор: `parser.demo-enabled=false`. Очистить учебную БД можно удалением
папки `data` **после остановки приложения**.

## 5. Тесты и сборка

```powershell
.\mvnw.cmd clean verify
java -jar target/review-parser-1.0.0.jar
```

Тесты проверяют вложенный JSON-LD, ошибочные блоки, отсутствие отзывов,
одновременные задания через настоящий HTTP-сервер, дедупликацию в H2,
сортировку, фильтрацию, пагинацию, HTTP-ошибки и валидацию.
Тестовая H2 находится в памяти; рабочая файловая БД не затрагивается.

Проверено на JDK 21: `verify` — 4 теста, 0 ошибок. Дополнительно проверен запуск
исполняемого JAR: автосбор сохранил 5 отзывов, повторные запуски по расписанию
не создали дублей. Maven Wrapper 3.9.9 также проверен.
